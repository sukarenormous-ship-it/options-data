# บทที่ 5 — การประมาณค่าและเลือกโมเดล

> **บทนี้ตอบ:** fit copula อย่างไรให้ตัวเลขที่ได้เชื่อถือได้ และจะรู้ได้อย่างไรว่ามันไม่เชื่อถือได้

---

## 5.1 สามขั้นตอน

```
1. ประมาณ marginal            →  ได้ u, v
2. ประมาณพารามิเตอร์ copula   →  ได้ θ̂
3. ตรวจสอบว่าโมเดลใช้ได้จริง  →  ได้ความมั่นใจ (หรือความไม่มั่นใจที่รู้ตัว)
```

ขั้นที่ 3 คือขั้นที่คนข้ามบ่อยที่สุด และเป็นขั้นที่มีค่าที่สุด

---

## 5.2 วิธีประมาณค่า

### วิธี 1 — Full MLE

ประมาณทุกอย่างพร้อมกัน: พารามิเตอร์ marginal และ copula

**ข้อดี:** efficient ทางทฤษฎี
**ข้อเสีย:** มิติสูง, ลู่เข้ายาก, และถ้า marginal misspecified จะลามไปพัง copula
**ในทางปฏิบัติ:** แทบไม่ใช้

### วิธี 2 — IFM (Inference Functions for Margins)

ทำสองขั้น: fit marginal ก่อน แล้วเอา u,v ที่ได้ไป fit copula

```
θ̂_marginal = argmax Σ log f(xᵢ; θ_m)      ← ทำแยกแต่ละสินทรัพย์
θ̂_copula   = argmax Σ log c(ûᵢ, v̂ᵢ; θ_c)  ← ตรึง marginal ไว้
```

**ข้อดี:** แยกปัญหาเป็นก้อนเล็ก เร็ว มั่นคง
**ข้อเสีย:** standard error ที่โปรแกรมรายงาน (จาก Hessian ของขั้นที่สอง)
ไม่ถูกต้อง เพราะไม่นับความไม่แน่นอนจากขั้นแรก — โดยทั่วไปจะแคบเกินจริง
แม้ทิศทางจะไม่ได้รับประกันในทางทฤษฎี ถ้าจะรายงาน CI ต้อง bootstrap
ทั้งสองขั้นพร้อมกัน

### วิธี 3 — CML (Canonical MLE) — วิธีที่แนะนำ

เหมือน IFM แต่ marginal ใช้ **empirical rank** ไม่สมมติรูปแบบ

```
ûᵢ = rank(xᵢ)/(n+1)
θ̂  = argmax Σ log c(ûᵢ, v̂ᵢ; θ)
```

**ข้อดี:** ไม่มีทาง misspecify marginal เลย ซึ่งกำจัดแหล่งความผิดพลาด
ที่ใหญ่ที่สุดตามบทที่ 2
**ข้อเสีย:** ไม่ extrapolate เกินข้อมูล และ rank หยาบเมื่อ n เล็ก

**นี่คือ default ที่ควรเริ่ม** ถ้าคุณกำลังจะเลือกวิธีแรกในชีวิต เลือกอันนี้

**ข้อควรระวังที่คนมองข้าม:** CML ก็เป็น two-stage เหมือนกัน การแทน F₁ ด้วย rank
ทำให้ asymptotic variance ของ θ̂ ไม่เท่ากับ inverse-Hessian ที่ optimizer คืนมา
(Genest, Ghoudi & Rivest, 1995) — SE ที่ scipy พิมพ์ออกมาจึงเชื่อไม่ได้เช่นกัน
ให้ bootstrap โดยสุ่มใหม่ตั้งแต่ข้อมูลดิบ ไม่ใช่จาก (u,v) ที่แปลงแล้ว

### วิธี 4 — Method of Moments ผ่าน τ

สำหรับ copula พารามิเตอร์เดียว ใช้ความสัมพันธ์ปิดกับ Kendall's τ ได้เลย:

```
Clayton:   θ̂ = 2τ̂ / (1 − τ̂)
Gumbel:    θ̂ = 1 / (1 − τ̂)
Gaussian:  ρ̂ = sin(π τ̂ / 2)
```

**ข้อดี:** ไม่ต้อง optimize เลย เร็วมาก มั่นคงมาก เหมาะกับ rolling window
ที่ต้อง refit หลายพันครั้ง
**ข้อเสีย:** ใช้ข้อมูลไม่หมด, ใช้กับ copula หลายพารามิเตอร์ไม่ได้

ในการทำ rolling backtest ผมมักใช้ τ-inversion เป็นตัวหลัก แล้วใช้ MLE
เป็นตัวตรวจสอบเป็นระยะ เพราะความเสถียรสำคัญกว่า efficiency
เมื่อคุณต้อง refit ทุกวันเป็นเวลา 3 ปี

## 5.3 เลือก family อย่างไร

### AIC / BIC

```
AIC = −2·logL + 2k
BIC = −2·logL + k·ln(n)
```

ใช้เรียงลำดับได้ แต่ **อย่าอ่านผู้ชนะเป็นความจริง** สิ่งที่ควรดูคือ
*ช่องว่าง* ระหว่างอันดับ ถ้า ΔAIC ระหว่างอันดับ 1 กับ 2 เท่ากับ 1.5
แปลว่าข้อมูลแยกสองโมเดลนี้ไม่ออก อย่าไปยึดว่าอันดับ 1 ถูก

### Goodness-of-fit test

วิธีมาตรฐานคือ Cramér–von Mises บน empirical copula:

```
S_n = Σ [ C_n(ûᵢ, v̂ᵢ) − C_θ̂(ûᵢ, v̂ᵢ) ]²
```

แล้วหา p-value ด้วย parametric bootstrap (Genest, Rémillard & Beaudoin, 2009)
เพราะ distribution ของ S_n ภายใต้ H₀ ขึ้นกับ family และ θ̂ จึงใช้ตาราง
สำเร็จรูปไม่ได้

**ระวังการตีความ:** p-value สูง ≠ โมเดลถูก มันแค่แปลว่า *ข้อมูลไม่พอ
จะปฏิเสธ* ที่ n = 250 คุณจะไม่ปฏิเสธอะไรเลยแทบทุกตัว นั่นไม่ใช่หลักฐาน
สนับสนุน มันคือหลักฐานว่าคุณมีข้อมูลน้อย

### เกณฑ์ที่ผมคิดว่าสำคัญกว่าทั้งสองอย่าง: ความเสถียร

fit ซ้ำบนหน้าต่างที่เลื่อนไปเรื่อย ๆ แล้ว plot `θ̂` ตามเวลา

- **เส้นนิ่ง** → โครงสร้างมีจริง เชื่อได้
- **เส้นกระโดดไปมา** → คุณกำลัง fit noise ต่อให้ AIC สวยแค่ไหน

กราฟเส้นเดียวนี้บอกเรื่องได้มากกว่าตาราง GOF ทั้งตาราง เพราะมันตอบคำถาม
ที่เราสนใจจริง ๆ: *พรุ่งนี้พารามิเตอร์นี้จะยังใช้ได้ไหม*

## 5.4 เลือกความยาวหน้าต่าง

การแลกที่หนีไม่พ้น:

```
หน้าต่างยาว   →  ประมาณค่านิ่ง  แต่  ตอบสนองการเปลี่ยน regime ช้า
หน้าต่างสั้น   →  ตอบสนองไว     แต่  ค่าที่ได้เต้นแรงจนอาจไร้ความหมาย
```

จุดที่คนพลาดคือ **จำนวนข้อมูลที่ใช้ประมาณ tail ไม่ใช่ n**

ถ้าหน้าต่างมี 250 วัน จุดที่อยู่ใน lower tail 5% ของตัวใดตัวหนึ่งมีแค่ **12 จุด**
และตัวเศษของ `λ̂_L` คือจุดที่อยู่ใน **มุมร่วม** ซึ่งเหลือจริงราว **3–8 จุด**
เท่านั้น ค่า `λ̂` ที่ได้จึงมี error bar กว้างมหาศาล ต่อให้ทศนิยมที่โปรแกรม
พิมพ์ออกมาจะมี 4 ตำแหน่งก็ตาม

> **กฎง่าย ๆ:** ถ้าคุณจะอ้างเรื่อง tail ให้นับก่อนว่ามีข้อมูลกี่จุดที่อยู่
> ใน tail นั้นจริง ๆ ถ้าต่ำกว่า 30 ให้พูดว่า "อาจจะ" ไม่ใช่ "ข้อมูลแสดงว่า"

อีกเรื่องคือ **effective sample size** ถ้าคุณใช้ overlapping window
หรือข้อมูลมี autocorrelation จำนวนข้อมูลอิสระจริงน้อยกว่า n มาก
CI ที่คำนวณแบบ iid จะแคบเกินจริง — ใช้ block bootstrap แทน

## 5.5 รายการตรวจสอบก่อนเชื่อผล fit

```
□ marginal กรอง vol dynamics แล้วหรือยัง (ไม่งั้น tail dependence อาจปลอม)
□ pseudo-observations แบนจริงไหม (plot histogram)
□ มีข้อมูลกี่จุดใน tail ที่คุณจะอ้างถึง
□ θ̂ นิ่งไหมเมื่อเลื่อนหน้าต่าง (plot θ̂ ตามเวลา)
□ ΔAIC ระหว่างอันดับ 1 กับ 3 ห่างพอจะแยกได้ไหม
□ ผลเปลี่ยนไหมถ้าเปลี่ยนความยาวหน้าต่าง ±50%
□ CI มาจาก bootstrap ที่นับ two-stage estimation แล้วหรือยัง
□ ลอง family ไปทั้งหมดกี่ตัว และรายงานครบไหม
```

ถ้าผ่านไม่ครบ ไม่ได้แปลว่าใช้ไม่ได้ แต่แปลว่าคุณต้องรู้ว่าคุณกำลังยืน
อยู่บนอะไร

## 5.6 กับดักที่พบบ่อย

**กับดัก 1 — pseudo-observation ที่มีค่าเป็น 0 หรือ 1**
copula density หลายตัวจะเป็นอนันต์ที่ขอบ ต้องหารด้วย `n+1` เสมอ
หรือ clip ไว้ที่ `[ε, 1−ε]`

**กับดัก 2 — ค่าซ้ำในข้อมูล (ties)**
ถ้าราคาไม่เปลี่ยน (ตลาดปิด, สินทรัพย์สภาพคล่องต่ำ) จะได้ rank ซ้ำ
ซึ่งละเมิดสมมติฐาน "marginal ต่อเนื่อง" ของ Sklar ทางแก้: ใช้ random tie-breaking
หรือกรองแถวเหล่านั้นออก แต่ต้องรู้ตัวว่าทำอะไรอยู่

**กับดัก 3 — look-ahead ผ่าน rank**
`rank(xᵢ)` คำนวณจากทั้งชุดข้อมูล ซึ่งรวมอนาคต! ใน backtest ต้องใช้
rank ที่คำนวณจากข้อมูลถึงเวลา t เท่านั้น นี่เป็น bug ที่เงียบมาก
เพราะ backtest จะออกมาดีขึ้นอย่างสมเหตุสมผลจนไม่มีใครสงสัย

**กับดัก 4 — optimizer ติดจุดต่ำสุดเฉพาะที่**
copula หลายตัวมี likelihood ที่แบนมากในบางช่วง ให้ลองหลาย starting point
และตรวจว่าค่าที่ได้อยู่ในขอบเขตที่ถูกต้อง (θ > 0 สำหรับ Clayton, θ ≥ 1
สำหรับ Gumbel)

## 5.7 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. เริ่มด้วย CML (empirical marginal + MLE บน copula) หรือ τ-inversion ถ้าต้อง refit ถี่
2. ความเสถียรของ θ̂ ข้ามหน้าต่าง บอกความจริงมากกว่า AIC หรือ p-value
3. tail ถูกประมาณจากข้อมูลไม่กี่จุดเสมอ — นับจำนวนจุดนั้นก่อนจะอ้างอะไร

## แบบฝึกหัด

**5.1** implement ทั้ง CML และ τ-inversion สำหรับ Clayton แล้วเทียบ θ̂
บนข้อมูลจริง ต่างกันเท่าไร ต่างกันมากขึ้นหรือน้อยลงเมื่อ n เล็กลง

**5.2** ทำ rolling fit หน้าต่าง 180 วัน กับคู่ (BTC, ETH) แล้ว plot θ̂
ตามเวลา พร้อมแถบ bootstrap CI เส้นนิ่งหรือเต้น

**5.3** สร้าง look-ahead bug ขึ้นมาโดยตั้งใจ (ใช้ rank จากทั้งชุด)
แล้วเทียบผล backtest กับเวอร์ชันที่ถูกต้อง ต่างกันเท่าไร
ตัวเลขนี้คือขนาดของ bias ที่คุณต้องระวังตลอดไป

**5.4** ทำ parametric bootstrap GOF test สำหรับ Clayton บนข้อมูลที่คุณ
สร้างเองจาก Gumbel ที่ n = 200 และ n = 2000 test จับได้ที่ n เท่าไร
