# บทที่ 2 — Sklar's Theorem และ PIT

> **บทนี้ตอบ:** แยก "หน้าตาของแต่ละตัว" ออกจาก "ความสัมพันธ์ระหว่างกัน" ได้อย่างไร
> และทำไมขั้นตอนแยกนี้คือจุดที่พังบ่อยที่สุดในทางปฏิบัติ

---

## 2.1 ความคิดหลัก ก่อนจะมีสมการ

ทุก joint distribution มีข้อมูลสองชั้นซ้อนกัน:

```
ข้อมูลของ ETH เดี่ยว ๆ  →  ETH เคลื่อนไหวแรงแค่ไหน เบ้ไหม หางหนาไหม
ข้อมูลของ SOL เดี่ยว ๆ  →  เหมือนกัน
─────────────────────────────────────────────────
ข้อมูลที่เหลือ          →  ทั้งคู่เคลื่อนที่ "ด้วยกัน" อย่างไร
```

Sklar's Theorem บอกว่าการแยกชั้นนี้ **ทำได้เสมอ และแยกได้แบบเดียว**
(เมื่อ marginal ต่อเนื่อง) นี่เป็นผลลัพธ์ที่แรงกว่าที่เห็นเมื่อมองผ่าน ๆ มาก —
มันบอกว่า "ความสัมพันธ์" เป็นวัตถุที่ดำรงอยู่ได้อย่างอิสระจาก
"การกระจายของแต่ละตัว" ไม่ใช่แค่คำพูดเชิงเปรียบเทียบ

---

## 2.2 Sklar's Theorem

ให้ `F(x,y)` เป็น joint CDF ของ (X,Y) และ `F₁, F₂` เป็น marginal CDF

**มี copula C ที่ทำให้**

```
F(x,y) = C( F₁(x), F₂(y) )     สำหรับทุก x, y
```

**และถ้า F₁, F₂ ต่อเนื่อง C นั้นมีเพียงตัวเดียว**

ในทางกลับกัน ถ้าเอา copula C ใด ๆ มาประกบกับ marginal ใด ๆ ผลที่ได้เป็น
joint distribution ที่ถูกต้องเสมอ — นี่คือส่วนที่ทำให้มันเป็นเครื่องมือ
สร้างแบบจำลอง ไม่ใช่แค่ทฤษฎีบทเชิงโครงสร้าง

**copula คืออะไรกันแน่**

C คือ CDF บน `[0,1]²` ที่มี marginal เป็น Uniform(0,1) ทั้งสองด้าน
เท่านั้นเอง เงื่อนไข "marginal เป็น uniform" คือกลไกที่ลบข้อมูลเรื่อง
scale ออกไปหมด เหลือแต่โครงสร้างความสัมพันธ์ล้วน ๆ

ในรูปความหนาแน่น:

```
f(x,y) = c(u,v) · f₁(x) · f₂(y)          โดย u = F₁(x), v = F₂(y)
```

`c` คือ copula density สังเกตว่า **ถ้า c ≡ 1 จะได้ f(x,y) = f₁(x)f₂(y)**
คือเป็นอิสระต่อกัน ดังนั้น copula density คือ "ตัวคูณที่บอกว่าเบี่ยงจาก
ความเป็นอิสระไปทางไหน แค่ไหน ณ จุดไหน" — เป็นวิธีตีความที่ใช้ได้ตลอดเล่ม

ผลพลอยได้ที่มีประโยชน์มากคือ log-likelihood แยกออกเป็นสองก้อน:

```
log L = Σ log c(uᵢ,vᵢ)  +  Σ log f₁(xᵢ)  +  Σ log f₂(yᵢ)
        └── dependence ─┘   └──── marginal ทั้งสองตัว ────┘
```

ซึ่งเป็นเหตุผลที่เรา fit marginal ก่อนแล้วค่อย fit copula ได้ (บทที่ 5)

## 2.3 PIT — เครื่องจักรที่ทำให้ทุกอย่างทำงาน

**Probability Integral Transform:** ถ้า X มี CDF ต่อเนื่อง `F₁` แล้ว

```
U = F₁(X)  ~  Uniform(0,1)
```

พูดเป็นภาษาคน: **แปลงค่าให้กลายเป็น percentile ของตัวเอง**

- BTC วันนี้ return −8% → ถ้านั่นคือ percentile ที่ 2 ของ BTC → u = 0.02
- ETH วันนี้ return −11% → ถ้านั่นคือ percentile ที่ 3 ของ ETH → v = 0.03

ตอนนี้เราเทียบ `u` กับ `v` ได้ตรง ๆ ทั้งที่ −8% กับ −11% เทียบกันไม่ได้
เพราะ vol ต่างกัน **นี่คือหัวใจ** — copula ทำงานบนภาษาของ percentile
ซึ่งเป็นภาษากลางที่ทุกสินทรัพย์พูดได้

ผลที่ตามมาที่สำคัญ: copula **invariant ต่อการแปลงแบบ monotone increasing**
จะใช้ราคา, log ราคา, หรือ return ก็ได้ copula ไม่เปลี่ยน ต่างจาก correlation
ที่เปลี่ยน (ข้อ 2 ในบทที่ 1)

---

## 2.4 ปัญหาในทางปฏิบัติ: เราไม่รู้ F₁

ทฤษฎีสวยงามเพราะสมมติว่ารู้ `F₁` จริง ในความเป็นจริงเราไม่รู้ มีสองทางเลือก

### ทาง A — Empirical (nonparametric)

ใช้อันดับของข้อมูลเอง:

```
ûᵢ = rank(xᵢ) / (n + 1)
```

หารด้วย `n+1` ไม่ใช่ `n` เพื่อไม่ให้มีค่าเป็น 1 พอดี (ซึ่งจะทำให้
copula density หลายตัวระเบิด) ผลลัพธ์เรียกว่า **pseudo-observations**

**ข้อดี:** ไม่ต้องสมมติรูปการกระจาย ไม่มีทางที่ marginal จะ misspecified
**ข้อเสีย:** ไม่ extrapolate เกินข้อมูลที่เคยเห็น และในหน้าต่างสั้น ๆ
ค่า rank จะหยาบมาก (n=60 → ความละเอียดแค่ 1/61)

### ทาง B — Parametric filter (copula-GARCH)

โมเดล marginal ให้เป็นเรื่องเป็นราวก่อน แล้วค่อย PIT บน residual:

```
1. fit ARMA-GARCH กับแต่ละสินทรัพย์
2. เอา standardized residual zᵢ = εᵢ/σᵢ ออกมา
3. PIT ผ่าน CDF ของ innovation ที่สมมติ (มัก skew-t)
4. fit copula บน (u,v) ที่ได้
```

**ข้อดี:** จัดการ vol clustering ได้ ซึ่งสำคัญมากในคริปโต
**ข้อเสีย:** เพิ่มพารามิเตอร์และเพิ่มโอกาส misspecified

### ทำไมเรื่องนี้สำคัญกว่าที่คิด

**ถ้า marginal ผิด → u, v ผิด → copula ที่ fit ได้ผิดทั้งดุ้น**

ตัวอย่างที่เห็นบ่อย: ไม่จัดการ vol clustering เลย เอา raw return มา PIT ตรง ๆ
ช่วงที่ vol สูง return ทุกตัวจะไปกระจุกอยู่ที่ปลายทั้งสองข้างของการกระจาย
พร้อม ๆ กัน ทำให้เห็น "tail dependence" ที่จริง ๆ แล้วเป็นแค่ **vol clustering
ที่เกิดพร้อมกัน** ไม่ใช่ dependence เชิงโครงสร้าง

คุณจะได้ Clayton θ สูงลิ่ว fit สวย และมันเป็นสิ่งประดิษฐ์ล้วน ๆ

> **กฎ:** ก่อนจะเชื่อ tail dependence ที่ fit ได้ ต้องตอบให้ได้ว่า
> คุณกรอง volatility dynamics ออกไปแล้วหรือยัง

## 2.5 ขอบเขต Fréchet–Hoeffding

copula ทุกตัวถูกบีบอยู่ระหว่างสองขอบนี้:

```
W(u,v) = max(u+v−1, 0)   ≤   C(u,v)   ≤   min(u,v) = M(u,v)
```

- `M` = **comonotonicity** — ตัวหนึ่งเป็นฟังก์ชันเพิ่มของอีกตัว (เหมือนกันทุกประการเชิงอันดับ)
- `W` = **countermonotonicity** — ตรงข้ามกันสมบูรณ์ (ใช้ได้เฉพาะ 2 มิติ)
- `Π(u,v) = uv` = **independence copula** — อยู่ตรงกลาง

มีประโยชน์เชิงปฏิบัติสองอย่าง: (1) ใช้ sanity-check ว่าโค้ดคุณคำนวณถูก
(2) เตือนว่าโครงสร้าง dependence มีเพดาน — ความสัมพันธ์ไม่สามารถ
"แรงกว่าเหมือนกันเป๊ะ" ได้

## 2.6 หน้าตาของขั้นตอนจริง

```
ราคา BTC, ราคา ETH
        ↓  log return
r_BTC, r_ETH
        ↓  (ทางเลือก) กรอง common factor ออกก่อน  ← บทที่ 11 จะบอกว่าทำไมนี่สำคัญมาก
residual e_BTC, e_ETH
        ↓  กรอง vol dynamics (GARCH) หรือ standardize
z_BTC, z_ETH
        ↓  PIT (empirical rank หรือ parametric CDF)
u, v  ∈ (0,1)
        ↓  fit copula
C(u,v; θ)
        ↓  h-function
สัญญาณ / การประเมินความเสี่ยง        ← บทที่ 7 และ 10
```

ทุกลูกศรคือจุดที่ทำพังได้ ลูกศรที่คนข้ามบ่อยที่สุดคือสองอันกลาง

---

## 2.7 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. Sklar: joint = marginal + copula เสมอ และแยกได้แบบเดียวเมื่อ marginal ต่อเนื่อง
2. PIT แปลงทุกอย่างเป็นภาษา percentile ทำให้สินทรัพย์ที่ vol ต่างกันเทียบกันได้
3. **marginal ผิด → copula ผิด** และความผิดพลาดที่พบบ่อยที่สุดคือไม่กรอง vol clustering
   ก่อน ซึ่งจะสร้าง tail dependence ปลอมขึ้นมา
