# บทที่ 12 — ออกแบบการทดลองให้ยุติธรรม

> **บทนี้ตอบ:** จะรู้ได้อย่างไรว่า copula *เพิ่ม* อะไรจริง ไม่ใช่แค่พูดซ้ำเรื่องเดิม
> ในรูปที่ซับซ้อนกว่า

---

## 12.1 คำถามที่ต้องถามให้ถูก

คำถามที่คนมักถาม: **"ระบบที่ใช้ copula ได้ Sharpe เท่าไร"**

คำถามที่ควรถาม: **"copula เพิ่มอะไรเหนือสิ่งที่ผมมีอยู่แล้ว"**

ความต่างสำคัญมาก เพราะระบบที่ใช้ copula อาจได้ Sharpe 1.3 ซึ่งฟังดูดี
แต่ถ้า baseline ที่ไม่ใช้ copula ได้ 1.25 คุณเพิ่งเพิ่มพารามิเตอร์ 7 ตัว
เพื่อ Sharpe 0.05 — ซึ่งเกือบแน่นอนว่าเป็น noise

---

## 12.2 การทดลองที่ยุติธรรม: ห้าแขน

ต้องเทียบแบบ apples-to-apples

| แขน | โครงสร้าง | สัญญาณ / บริบท |
|---|---|---|
| **A** | PCA residual | z-score / ranking ธรรมดา |
| **B** | PCA residual | OU / AR mean reversion |
| **C** | PCA residual | Copula conditional mispricing |
| **D** | PCA residual | OU + Copula ยืนยันร่วมกัน |
| **E** | PCA residual | สัญญาณง่าย + Copula risk overlay |

**ทุกแขนต้องใช้เงื่อนไขเดียวกันทุกประการ:**

```
□ universe เดียวกัน (รวมเหรียญที่ delist ไปแล้ว — ระวัง survivorship)
□ formation / trading window เดียวกัน
□ transaction cost เดียวกัน
□ funding / borrow / slippage assumption เดียวกัน
□ sizing และ risk budget เดียวกัน
□ execution delay เดียวกัน
□ จำนวนสถานะสูงสุดเท่ากัน
□ ช่วงเวลาทดสอบเดียวกัน
□ seed เดียวกัน (ถ้ามีส่วนสุ่ม)
```

ถ้าข้อใดข้อหนึ่งต่างกัน คุณกำลังเทียบสองสิ่งที่เทียบไม่ได้ และผลต่าง
ที่เห็นอาจมาจากข้อนั้นทั้งหมด

**การเปรียบเทียบที่มีค่าที่สุดคือ B กับ D** — ถามตรง ๆ ว่า
copula เพิ่มอะไรเหนือ mean reversion ธรรมดา

---

## 12.3 การทดสอบแก่นกลาง: incremental information

Sharpe เป็นตัวชี้วัดที่หยาบเกินไปสำหรับคำถามนี้ ตัวที่ตรงกว่าคือ
**สัญญาณ copula ยังบอกอะไรเพิ่ม หลังจากรู้สัญญาณ OU แล้วหรือไม่**

### วิธีที่ 1 — Double sort

แบ่งข้อมูลเป็นตาราง 5×5 ตามสัญญาณทั้งสอง แล้วดูผลตอบแทนข้างหน้าในแต่ละช่อง

```
                    สัญญาณ Copula
                Q1    Q2    Q3    Q4    Q5
         Q1  [    ][    ][    ][    ][    ]
สัญญาณ   Q2  [    ][    ][    ][    ][    ]
  OU     Q3  [    ][    ][    ][    ][    ]
         Q4  [    ][    ][    ][    ][    ]
         Q5  [    ][    ][    ][    ][    ]
```

**สิ่งที่ต้องดู:** ภายในแถวเดียวกัน (OU คงที่) ผลตอบแทนเปลี่ยนตาม
คอลัมน์ไหม

- **ถ้าเปลี่ยน** → copula มีข้อมูลเพิ่มจริง
- **ถ้าไม่เปลี่ยน** → copula พูดซ้ำเรื่องเดิม ตัดออกได้เลย

นี่คือการทดสอบที่ตรงกับคำถามที่สุด และอ่านง่ายกว่าตัวเลขสถิติใด ๆ

### วิธีที่ 2 — Orthogonalized regression

ถอดส่วนที่ซ้ำกับ OU ออกจากสัญญาณ copula ก่อน:

```
ขั้น 1:  S_cop = a + b·S_OU + ε        →  เก็บ ε ไว้ (ส่วนที่ไม่ซ้ำ)
ขั้น 2:  R_fwd = α + β₁·S_OU + β₂·ε + u
```

**ถ้า β₂ ไม่ต่างจากศูนย์อย่างมีนัยสำคัญ copula ไม่เพิ่มอะไร**

ใช้ standard error ที่ทนต่อ autocorrelation (Newey–West) หรือ
block bootstrap เสมอ เพราะข้อมูลรายวันของ residual มี autocorrelation
และ t-stat ปกติจะโกหก

### วิธีที่ 3 — เปรียบเทียบ conditional expectation ตรง ๆ

```
E[ R_fwd | OU ]              =  ?
E[ R_fwd | OU ∩ Copula ]     =  ?
```

ถ้า

```
E[R | OU ∩ Copula]  >  E[R | OU]     อย่างเสถียรใน OOS
```

copula มีมูลค่า แต่ถ้า

```
E[R | OU ∩ Copula]  ≈  E[R | OU]
```

copula แค่พูดซ้ำเรื่องเดิมในรูปที่ซับซ้อนกว่า — **ตัดออก**

## 12.4 มาตรวัดที่ต้องดู ไม่ใช่แค่ Sharpe

```
ด้านสัญญาณ
  □ forward return แยกตามถังสัญญาณ (ต้อง monotone)
  □ IC และ rank IC
  □ hit rate
  □ payoff ratio (กำไรเฉลี่ย / ขาดทุนเฉลี่ย)

ด้านต้นทุน
  □ turnover
  □ ต้นทุนต่อเทรด
  □ ระยะเวลาถือครองเฉลี่ย
  □ Sharpe ก่อนหักต้นทุน เทียบกับหลังหัก  ← ช่องว่างนี้บอกความเปราะบาง

ด้านความเสี่ยง
  □ MaxDD และระยะเวลาฟื้นตัว
  □ tail loss (CVaR)
  □ exposure ต่อ BTC / common factor ที่เหลืออยู่
  □ residual correlation ระหว่างสถานะ
  □ effective breadth (บทที่ 10)

ด้านความทนทาน
  □ regime stability (แบ่งช่วงเวลาแล้วดูแยก)
  □ parameter sensitivity (เปลี่ยนพารามิเตอร์ ±30% ผลเปลี่ยนแค่ไหน)
  □ walk-forward degradation (IS เทียบ OOS)
```

**สิ่งที่สำคัญที่สุดในรายการนี้คือ monotonicity**

```
|สัญญาณ| ↑   ⟹   E[R_อนาคต] ↑
```

ถ้าสัญญาณแรงขึ้นแล้วผลตอบแทนไม่ดีขึ้นตาม แปลว่าสิ่งที่คุณจับได้
ไม่ใช่ edge เชิงเศรษฐศาสตร์ที่มีโครงสร้าง แต่เป็นเหตุการณ์ไม่กี่ครั้ง
ที่บังเอิญเข้าทาง — และมันจะไม่เกิดซ้ำ

## 12.5 การตรวจสอบความทนทาน

**Walk-forward**

```
[─── fit ───][ทดสอบ]
      [─── fit ───][ทดสอบ]
            [─── fit ───][ทดสอบ]
```

พารามิเตอร์ทั้งหมด — รวมถึง **การเลือก family** และ **threshold** —
ต้องถูกเลือกจากช่วง fit เท่านั้น ถ้าคุณเลือก family ครั้งเดียวจากทั้งชุด
แล้วรัน walk-forward คุณยังมี look-ahead อยู่

**Purge และ embargo**

ถ้าสัญญาณใช้ข้อมูลย้อนหลัง N วัน และผลตอบแทนวัดไปข้างหน้า h วัน
ต้องเว้นช่วงระหว่าง train กับ test อย่างน้อย `N + h` วัน ไม่งั้นข้อมูลรั่ว

**Sensitivity ที่ควรทำเป็นมาตรฐาน**

| เปลี่ยน | ผลควรเป็นอย่างไร |
|---|---|
| ความยาวหน้าต่าง ±50% | ผลควรอยู่ในทิศเดียวกัน |
| threshold ±30% | ผลควรเปลี่ยนแบบราบรื่น ไม่ใช่กระโดด |
| family เปลี่ยนตัว | ผลไม่ควรพลิกจากบวกเป็นลบ |
| ต้นทุน ×2 | บอกว่า margin ของคุณบางแค่ไหน |
| execution delay +1 บาร์ | **นี่คือการทดสอบที่โหดที่สุดและสำคัญที่สุด** |

**ถ้าผลพังเมื่อเลื่อนการเข้า 1 บาร์ คุณไม่ได้มี edge คุณมี microstructure noise**
(บทที่ 8 หัวข้อ 8.5)

## 12.6 ข้อผิดพลาดที่ทำให้ผลไม่มีความหมาย

**1. Survivorship bias**
ถ้า universe ของคุณคือเหรียญที่ยังอยู่วันนี้ คุณเพิ่งลบทุกกรณีที่
"ความสัมพันธ์พังถาวร" ออกไปหมด ซึ่งเป็นกรณีที่สำคัญที่สุดสำหรับ
การประเมินกลยุทธ์ mean reversion

**2. ต้นทุนที่ไม่สมจริง**
ในคริปโตต้องนับ: taker fee, spread, slippage ตามขนาด, funding
สำหรับ perp, และค่า borrow ถ้า short spot **ถ้า turnover สูง
ต้นทุนจะเป็นตัวตัดสิน ไม่ใช่สัญญาณ**

**3. เทสหลายครั้งแล้วรายงานครั้งเดียว**
ถ้าลอง 200 การตั้งค่า อันที่ดีที่สุดจะดูดีเสมอแม้ทุกอันไร้ค่า
ให้บันทึกจำนวนการทดลองทั้งหมด และดูการกระจายของผล ไม่ใช่แค่ค่าสูงสุด
(deflated Sharpe ของ Bailey & López de Prado เป็นเครื่องมือที่ตรงประเด็น)

**4. เปรียบเทียบกับ baseline ที่อ่อนโดยตั้งใจ**
ถ้า baseline ของคุณคือ z-score ที่ไม่ปรับแต่งอะไรเลย ขณะที่แขน copula
ถูกจูนมาอย่างดี การเปรียบเทียบนั้นไม่มีความหมาย **จูน baseline
ให้ดีเท่าที่คุณจูนตัวที่คุณอยากให้ชนะ**

ข้อ 4 นี้เป็นอคติที่เกิดขึ้นเองโดยไม่ตั้งใจเกือบทุกครั้ง เพราะคน
ใช้เวลากับสิ่งที่ตัวเองสนใจมากกว่า

## 12.7 การตัดสินใจ

หลังทำครบแล้ว ตัดสินตามตารางนี้:

| ผลที่ได้ | การตัดสินใจ |
|---|---|
| D > B อย่างชัดเจนและเสถียรทุกช่วงเวลา | เก็บ copula ไว้ในสาย alpha |
| D ≈ B แต่ E > B (ความเสี่ยงลดลง) | เก็บ copula ไว้เป็น risk overlay เท่านั้น |
| D ≈ B และ E ≈ B | **ตัด copula ออก** |
| C > B (copula เดี่ยวชนะ OU) | ตรวจซ้ำอย่างระแวง — ผลนี้ขัดกับทฤษฎีในบทที่ 8 |
| ผลพลิกไปมาตามช่วงเวลา | ยังไม่มีข้อสรุป ต้องการข้อมูลมากกว่านี้ |

แถวสุดท้ายเป็นคำตอบที่ถูกต้องบ่อยกว่าที่คนอยากยอมรับ
**"ยังไม่รู้" เป็นข้อสรุปที่ซื่อสัตย์และมีค่ากว่าการเลือกข้างโดยไม่มีหลักฐาน**

---

## 12.8 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. ถามว่า copula *เพิ่ม* อะไรเหนือ baseline ไม่ใช่ว่าระบบที่มี copula ได้เท่าไร
2. Double sort และ orthogonalized regression ตอบคำถามนี้ตรงกว่า Sharpe
3. จูน baseline ให้ดีเท่าที่จูนตัวที่คุณอยากให้ชนะ ไม่งั้นการทดลองไม่มีความหมาย

## แบบฝึกหัด

**12.1** สร้างทั้ง 5 แขนด้วยเงื่อนไขเดียวกันทุกข้อ รายงานเป็นตารางเดียว
พร้อมมาตรวัดในหัวข้อ 12.4 ทั้งหมด

**12.2** ทำ double sort 5×5 ระหว่างสัญญาณ OU กับ MI แล้ววาดเป็น heatmap
อ่านออกไหมว่า copula เพิ่มอะไร

**12.3** ทำ orthogonalized regression พร้อม Newey–West standard error
`β₂` มีนัยสำคัญไหม แล้วถ้าใช้ t-stat ธรรมดาล่ะ ต่างกันแค่ไหน

**12.4** ทำการทดสอบ execution delay: +0, +1, +2 บาร์ วาดกราฟ Sharpe
เทียบ delay ความชันของกราฟนี้คือความเปราะบางของกลยุทธ์คุณ

**12.5** นับจำนวนการตั้งค่าทั้งหมดที่คุณเคยลองกับข้อมูลชุดนี้ตั้งแต่ต้น
แล้วคำนวณว่าค่าสูงสุดที่คาดหวังได้จากการลองเท่านั้นครั้งกับข้อมูลสุ่มล้วน
คือเท่าไร ผลจริงของคุณสูงกว่านั้นไหม
