# บทที่ 7 — จาก copula เป็นสัญญาณ

> **บทนี้ตอบ:** h-function คืออะไร แปลงเป็นสัญญาณเทรดอย่างไร และตัวเลขที่ได้
> หมายความว่าอะไรจริง ๆ
>
> **อ่านบทนี้พร้อมความระแวงไว้ก่อน:** บทนี้สร้างสัญญาณขึ้นมาอย่างที่งานวิจัย
> ส่วนใหญ่ทำ ส่วนบทถัดไปจะรื้อว่าสัญญาณนั้นแปลว่าอะไรกันแน่ —
> สองบทนี้เป็นคู่กัน อย่าอ่านบทนี้จบแล้วเอาไปใช้เลย

---

## 7.1 h-function — เครื่องมือชิ้นเดียวที่ต้องรู้

```
h(u | v) = ∂C(u,v)/∂v = P( U ≤ u | V = v )
```

อ่านเป็นภาษาคน:

> **"ถ้ารู้ว่าสินทรัพย์ B อยู่ที่ percentile v ณ ตอนนี้
> ความน่าจะเป็นที่สินทรัพย์ A จะอยู่ต่ำกว่าหรือเท่ากับ percentile u คือเท่าไร"**

เทียบกับกรณีอ้างอิงเสมอ:

```
ถ้าเป็นอิสระต่อกัน:  h(u|v) = u        (รู้ B ไม่ช่วยอะไรเลย)
ถ้าไม่เป็นอิสระ:     h(u|v) ≠ u        (รู้ B แล้วมุมมองต่อ A เปลี่ยน)
```

**ระยะห่างระหว่าง `h(u|v)` กับ `u` คือปริมาณข้อมูลที่ B ให้เกี่ยวกับ A**
และนั่นคือสิ่งที่ copula เพิ่มเข้ามาเหนือการดูสินทรัพย์เดี่ยว ๆ

---

## 7.2 ตัวอย่างเชิงตัวเลข ที่ทำให้เห็นภาพทั้งหมด

ใช้ Clayton copula θ = 2 (ซึ่งเท่ากับ τ = 0.5, λ_L = 0.71, λ_U = 0)

สูตร:
```
h(u|v) = v^(−θ−1) · ( u^(−θ) + v^(−θ) − 1 )^(−1/θ − 1)
```

**สถานการณ์ A: ETH อยู่ percentile 15, SOL อยู่ percentile 60**

```
h(0.15 | 0.60) = 0.0147
```

ตีความ: เมื่อรู้ว่า SOL อยู่ค่อนไปทางสูง โอกาสที่ ETH จะต่ำขนาดนี้
มีแค่ **1.5%** ทั้งที่ถ้าดู ETH เดี่ยว ๆ มันคือเหตุการณ์ 15%

→ **ETH ต่ำผิดปกติ เมื่อเทียบกับที่ SOL บอก**

**สถานการณ์ B: ETH อยู่ percentile 15, SOL อยู่ percentile 10**

```
h(0.15 | 0.10) = 0.582
```

ตีความ: เมื่อรู้ว่า SOL ก็ต่ำเหมือนกัน การที่ ETH อยู่ที่ 15 เป็นเรื่อง
**ธรรมดามาก** (58%)

→ **ไม่มีอะไรผิดปกติเลย**

**นี่คือประเด็นทั้งหมดของบทนี้:** `u = 0.15` เท่ากันทั้งสองกรณี
z-score ของ ETH เท่ากัน แต่ข้อสรุปกลับด้านกันสิ้นเชิง เพราะบริบทต่างกัน
สิ่งที่ copula ให้คือ **บริบท** ไม่ใช่ทิศทาง

## 7.3 Mispricing Index

นิยามที่ใช้กันในสายงาน pairs trading (Xie, Liew, Wu & Zou, 2016):

```
MI_{A|B} = h(u_A | v_B) − 0.5
MI_{B|A} = h(v_B | u_A) − 0.5
```

ช่วงค่า `[−0.5, +0.5]` และอ่านว่า:

```
MI  ≈  0     →  A อยู่ตรงกลางของสิ่งที่ B บอกให้คาด  (ปกติ)
MI  <<  0    →  A ต่ำกว่าที่ควรเป็นเมื่อรู้ B         (A ถูกเกินไป?)
MI  >>  0    →  A สูงกว่าที่ควรเป็นเมื่อรู้ B         (A แพงเกินไป?)
```

**สังเกตเครื่องหมายคำถาม** — คำว่า "ถูกเกินไป" นั้นเป็นการตีความที่เรา
ใส่เข้าไปเอง ไม่ใช่สิ่งที่คณิตศาสตร์บอก คณิตศาสตร์บอกแค่ว่า "หายาก"
บทที่ 8 คือบทที่พูดถึงช่องว่างนี้ทั้งบท

### Cumulative MI

MI รายวันเต้นแรงมาก งานส่วนใหญ่จึงสะสมมัน:

```
M_t = Σ (MI_s)   ตั้งแต่ s = t₀ ถึง t
```

แล้วเทรดจาก `M_t` แทน — เข้าเมื่อ `M` เกิน threshold, ออกเมื่อกลับสู่ 0

**นี่คือจุดที่ต้องระวัง:** การสะสมค่าสร้างแนวโน้มขึ้นมาเอง แม้ข้อมูล
จะสุ่มล้วน (random walk ก็ "trend" ได้) และการรีเซ็ต `t₀` เป็นพารามิเตอร์
ซ่อนที่มีอิทธิพลต่อผลลัพธ์มาก ต้องทดสอบความไวต่อมันเสมอ

---

## 7.4 กฎการเทรดที่พบบ่อย

```
เปิดสถานะ:
    ถ้า M_t < −D   →  ซื้อ A, ขาย B
    ถ้า M_t > +D   →  ขาย A, ซื้อ B

ปิดสถานะ:
    ถ้า M_t กลับมาแตะ 0
    หรือถือครบ H วัน (time stop)
    หรือขาดทุนเกิน S (loss stop)
```

พารามิเตอร์ที่ต้องเลือก: `D`, `H`, `S`, ความยาวหน้าต่าง fit, family,
ความถี่ refit, จุดรีเซ็ต `t₀`

**นับดู: อย่างน้อย 7 ตัว** และแต่ละตัวคือช่องทาง overfit
เก็บตัวเลขนี้ไว้ในใจตอนอ่านบทที่ 12 และ 13

## 7.5 ทางเลือกอื่นในการสร้างสัญญาณ

**Conditional expectation** — แทนที่จะใช้ความน่าจะเป็น ใช้ค่าคาดหวัง:
```
E[U | V = v]  แล้วเทียบกับ u ที่สังเกตจริง
```
ตีความง่ายกว่าในบางบริบท แต่ต้องอินทิเกรตเชิงตัวเลข

**Joint tail probability** — ใช้เป็นตัวกรองความเสี่ยง ไม่ใช่สัญญาณเข้า:
```
P(U ≤ 0.05, V ≤ 0.05) = C(0.05, 0.05)
```
ถ้าค่านี้สูงผิดปกติ แปลว่าคู่นี้มีโอกาสพังพร้อมกัน — ควรลด size
(บทที่ 10)

**Conditional quantile band** — หาช่วง `[u_lo, u_hi]` ที่ `h(u_lo|v)=0.05`
และ `h(u_hi|v)=0.95` แล้วดูว่า u ปัจจุบันหลุดกรอบไหม
เป็นวิธีที่อธิบายให้คนอื่นฟังง่ายที่สุด

## 7.6 ข้อผิดพลาดที่ต้องหลีกเลี่ยงตอน implement

**1. ใช้ราคาแทน residual**

ถ้าเอา return ดิบของ ETH กับ SOL มาเข้า copula ตรง ๆ สัญญาณที่ได้จะถูก
ครอบงำโดย BTC beta — วันที่ตลาดลงทั้งกระดาน u และ v จะต่ำพร้อมกันเสมอ
และ copula จะบอกว่า "ปกติ" ทุกครั้ง สัญญาณที่คุณอยากได้อยู่ใน
**ส่วนที่เหลือหลังหัก common factor** (บทที่ 11)

**2. ลืม h-function มีสองทิศ**

`h(u|v)` กับ `h(v|u)` ไม่เท่ากันและให้คนละคำตอบ กฎการเทรดต้องระบุชัด
ว่าใช้ทิศไหน หรือใช้ทั้งคู่และต้องการให้ทั้งสองเห็นตรงกัน
(อย่างหลังเป็นตัวกรองที่เข้มกว่าและมักดีกว่า)

**3. Look-ahead ผ่าน rank**

ย้ำจากบทที่ 5 เพราะเป็น bug ที่พบบ่อยที่สุดในโค้ด backtest ของงานสาย copula
`u_t` ต้องคำนวณจาก CDF ที่ประมาณด้วยข้อมูลถึง `t−1` เท่านั้น

**4. เชื่อทศนิยม**

`h = 0.0147` ดูแม่นยำ แต่มันคำนวณจาก θ̂ ที่ประมาณได้จากข้อมูลจำกัด
ถ้า θ อยู่ในช่วง [1.5, 2.5] ตามความไม่แน่นอน ค่า h จะอยู่ในช่วงกว้างแค่ไหน
ควรคำนวณดูสักครั้งเพื่อรู้ขนาดของความไม่แน่นอนจริง

**5. Threshold ที่เลือกจากผลลัพธ์**

ถ้า `D` ถูกเลือกเพราะให้ Sharpe สูงสุดในชุดข้อมูลเดียวกับที่วัดผล
ตัวเลข Sharpe นั้นไม่มีความหมาย ต้องเลือกด้วย walk-forward เท่านั้น

## 7.7 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. `h(u|v)` ตอบว่า "สถานะนี้หายากแค่ไหนเมื่อรู้สถานะของอีกตัว" —
   ระยะห่างจาก `u` คือปริมาณข้อมูลที่เพิ่มขึ้น
2. u เดียวกันให้ข้อสรุปตรงข้ามได้ ขึ้นกับ v — นี่คือมูลค่าที่แท้จริงของ copula
3. กฎเทรดจาก MI มีพารามิเตอร์อย่างน้อย 7 ตัว นับให้ครบก่อนเชื่อ backtest

## แบบฝึกหัด

**7.1** implement `h(u|v)` สำหรับ Clayton, Gumbel และ Gaussian แล้วยืนยัน
ว่าที่ dependence → 0 ทุกตัวลู่เข้าหา `h(u|v) = u`

**7.2** วาด heatmap ของ `h(u|v)` บน [0,1]² สำหรับ Clayton θ=2
บริเวณไหนที่ h ต่างจาก u มากที่สุด นั่นคือบริเวณที่ copula มีอะไรจะบอก

**7.3** คำนวณ `h(0.15|0.60)` สำหรับ θ = 1.5, 2.0, 2.5
ช่วงของคำตอบกว้างแค่ไหน นี่คือความไม่แน่นอนที่ส่งผ่านจากการประมาณค่า

**7.4** สร้างอนุกรม MI และ cumulative MI ของคู่ (ETH, SOL) หนึ่งปี
แล้ว plot คู่กับ spread ปกติ สองเส้นนี้บอกเรื่องเดียวกันหรือคนละเรื่อง
