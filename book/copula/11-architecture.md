# บทที่ 11 — สถาปัตยกรรม StatArb

> **บทนี้ตอบ:** โมเดลแต่ละตัวมีหน้าที่อะไร วางลำดับอย่างไร และ copula ควรอยู่ตรงไหน

---

## 11.1 ความเข้าใจผิดที่ต้องทิ้งก่อน

คำถามที่คนส่วนใหญ่เริ่มต้นคือ **"โมเดลไหนดีที่สุดสำหรับ StatArb"**

คำถามนี้ผิดตั้งแต่ต้น เพราะ StatArb **ไม่ใช่โมเดลตัวเดียว มันคือสถาปัตยกรรม**

โมเดลแต่ละชนิดตอบคนละคำถาม และคุณต้องการคำตอบของทุกคำถาม:

| องค์ประกอบ | คำถามที่มันตอบ |
|---|---|
| **Factor Model** | อะไรคือการเคลื่อนไหวร่วม |
| **Cointegration / OU / AR** | อะไรมีดุลยภาพหรือแนวโน้มจะกลับ |
| **Copula** | สถานะร่วมตอนนี้ผิดปกติไหม |
| **Portfolio Optimizer** | ควรถืออะไรเท่าไร |
| **Risk Model** | ที่ดูเหมือนกระจาย จริง ๆ เกี่ยวกันแค่ไหน โดยเฉพาะที่ tail |
| **Execution** | edge ที่เห็นเหลือเงินจริงหลังต้นทุนไหม |

การถามว่า "OU ดีกว่า copula ไหม" เหมือนถามว่า "เครื่องยนต์ดีกว่าเบรกไหม"
มันคนละหน้าที่

---

## 11.2 สถาปัตยกรรมที่แนะนำ

```
                  ┌─────────────────────┐
                  │   Market Returns    │
                  └──────────┬──────────┘
                             ↓
                  ┌─────────────────────┐
                  │ Common Factor Model │   PCA / BTC beta / sector
                  └──────────┬──────────┘
                             ↓
                  ┌─────────────────────┐
                  │      Residuals      │   ← ทุกอย่างหลังจากนี้ทำบน residual
                  └──────────┬──────────┘
                             ↓
              ┌──────────────┴──────────────┐
              ↓                             ↓
    ┌───────────────────┐         ┌───────────────────┐
    │   ALPHA           │         │  CONTEXT / RISK   │
    │  z-score / OU /   │         │      Copula       │
    │  ranking          │         │  conditional +    │
    │                   │         │  tail dependence  │
    └─────────┬─────────┘         └─────────┬─────────┘
              └──────────────┬──────────────┘
                             ↓
                  ┌─────────────────────┐
                  │  Portfolio Sizing   │
                  └──────────┬──────────┘
                             ↓
                  ┌─────────────────────┐
                  │   Neutralization    │   factor / beta / sector
                  └──────────┬──────────┘
                             ↓
                  ┌─────────────────────┐
                  │ Execution + Costs   │
                  └──────────┬──────────┘
                             ↓
                  ╔═════════════════════╗
                  ║    NET OOS P&L      ║   ← ลูกศรนี้สำคัญที่สุด
                  ╚═════════════════════╝
```

**ลูกศรสุดท้ายคือลูกศรที่ตัดสินทุกอย่าง** ไม่ว่า PCA, OU, cointegration
หรือ copula จะสวยทางคณิตศาสตร์แค่ไหน ถ้า

```
Net OOS Edge ≤ 0
```

มันยังไม่ใช่ trading edge

## 11.3 ทำไมต้องหัก common factor ก่อน — เหตุผลเชิงตัวเลข

นี่คือขั้นตอนที่คนข้ามบ่อยที่สุดและเสียหายมากที่สุดในคริปโต

**ถ้าไม่หัก:** สิ่งที่คุณคิดว่าเป็นสัญญาณ relative value ส่วนใหญ่คือ
"altcoin beta" ปลอมตัวมา 20 คู่ที่คุณถือคือเดิมพันเดียวกัน 20 ครั้ง
(บทที่ 10)

**ตัวเลขจริงในคริปโต:**

```
สัดส่วนความแปรปรวนที่อธิบายได้ด้วย PC1  ≈  60–80%
```

แปลว่า **ข้อมูลส่วนใหญ่ที่คุณเห็นคือตลาด ไม่ใช่สินทรัพย์**
ถ้าไม่หักออก คุณกำลังโมเดลตลาดซ้ำ 20 ครั้ง

**หักอย่างไร — สามทางเลือก เรียงตามความซับซ้อน**

```
1. BTC beta        e_i = r_i − β_i · r_BTC
2. PCA k factor    e_i = r_i − Σ β_ik · f_k
3. Sector + market  ซับซ้อนกว่า สำหรับ universe ใหญ่
```

ทางที่ 1 ง่ายที่สุดและใช้ได้ดีน่าประหลาดใจในคริปโต เพราะ BTC เป็น
factor ที่ครอบงำจริง ๆ **เริ่มจากอันนี้**

**ประเด็นที่ต้องระวัง:** `β` ต้องประมาณจากข้อมูลอดีตเท่านั้น (rolling)
และ `β` ในคริปโตไม่นิ่ง — ควร plot มันตามเวลาก่อนใช้

## 11.4 ทำไม copula ควรอยู่ในสาย "context" ไม่ใช่สาย "alpha"

จากบทที่ 8 เรารู้แล้วว่า copula ไม่บรรจุข้อมูลเรื่องเวลา
ดังนั้นการวางมันเป็นเครื่องกำเนิดสัญญาณหลักคือการขอให้มันทำสิ่งที่
มันทำไม่ได้โดยโครงสร้าง

การวางที่ถูกต้องคือให้มันตอบสิ่งที่โมเดล alpha ตอบไม่ได้:

| คำถาม | ใครตอบ |
|---|---|
| residual นี้เบี่ยงจากค่าเฉลี่ยกี่ sigma | z-score |
| มันมีแนวโน้มกลับไหม เร็วแค่ไหน | OU / AR |
| **สถานะร่วมกับสินทรัพย์อื่นนี้ ผิดปกติจริงไหม** | **copula** |
| ถ้าเข้าคู่นี้ พอร์ตจะกระจุกตัวขึ้นไหม | **copula (tail)** |

**การรวมสัญญาณสองแบบมีสองรูปแบบที่ต่างกันมาก**

**รูปแบบ AND (ตัวยืนยัน)**
```
เข้าเมื่อ:  |z| > 2  AND  |MI| > D
```
กรองเข้ม เทรดน้อยลง คุณภาพต่อเทรดสูงขึ้น (ถ้าสองสัญญาณตอบคนละคำถามจริง)

**รูปแบบ OVERLAY (ปรับขนาด)**
```
size = f(z) · g(tail crowding จาก copula)
```
ไม่ตัดเทรด แต่ปรับขนาดตามความเสี่ยงที่ copula เห็น

รูปแบบที่สองมักให้ผลดีกว่าในทางปฏิบัติ เพราะไม่ลด breadth
(ซึ่งเราเพิ่งเห็นในบทที่ 10 ว่ามีน้อยอยู่แล้ว)

---

## 11.5 คำถามที่ต้องตอบได้ก่อนเพิ่มชั้นใด ๆ

ก่อนใส่ copula (หรืออะไรก็ตาม) เข้าไปในระบบ ต้องตอบสามข้อนี้ได้:

**1. ชั้นนี้ตอบคำถามอะไรที่ชั้นที่มีอยู่ตอบไม่ได้**
ถ้าตอบไม่ได้เป็นข้อความชัด ๆ อย่าใส่

**2. ถ้ามันช่วยจริง จะเห็นอะไรในข้อมูล**
เขียนคำทำนายออกมาก่อนรัน backtest เช่น "ถ้า copula ช่วยจริง
hit rate ของเทรดที่ผ่านตัวกรองควรสูงกว่าที่ไม่ผ่านอย่างน้อย 3 จุด"

**3. ถ้ามันไม่ช่วย จะรู้ได้อย่างไร**
ถ้าไม่มีผลลัพธ์ใดที่จะทำให้คุณเอามันออก แปลว่าคุณไม่ได้กำลังทดสอบอะไร

ข้อ 3 คือข้อที่คนละเลยมากที่สุด และเป็นเส้นแบ่งระหว่างการวิจัย
กับการหาเหตุผลสนับสนุนสิ่งที่อยากทำอยู่แล้ว

---

## 11.6 ลำดับการสร้างที่ผมแนะนำ

อย่าสร้างทั้งระบบพร้อมกัน สร้างทีละชั้นและวัดผลทุกชั้น

```
สัปดาห์ 1:  factor model + residual + z-score          →  วัด baseline
สัปดาห์ 2:  เพิ่ม OU / half-life filter                 →  วัดส่วนเพิ่ม
สัปดาห์ 3:  เพิ่มต้นทุนจริงและ execution delay          →  วัดว่ายังเหลือไหม
สัปดาห์ 4:  เพิ่ม copula เป็น context                   →  วัดส่วนเพิ่ม
สัปดาห์ 5:  เพิ่ม copula tail overlay ใน sizing         →  วัดส่วนเพิ่ม
```

**สังเกตว่าต้นทุนเข้ามาตั้งแต่สัปดาห์ 3 ไม่ใช่สัปดาห์สุดท้าย**
เพราะถ้า edge ตายด้วยต้นทุน คุณไม่ควรเสียเวลาสองสัปดาห์ถัดไปเลย

การจัดลำดับแบบนี้ยังให้ของแถมสำคัญ: คุณจะมีตัวเลข baseline ที่ชัดเจน
สำหรับตอบคำถามในบทที่ 12 ว่า **copula เพิ่มอะไร**

---

## 11.7 นิยาม StatArb ที่แม่นที่สุด

หลังจากรื้อทุกชิ้นส่วนแล้ว:

> **Statistical Arbitrage คือการหา relative mispricing หรือ predictable
> residual structure ด้วยแบบจำลองเชิงสถิติ จากนั้นสร้าง long-short portfolio
> ที่ลด common risk และอาศัยการเดิมพันจำนวนมากที่มี edge เล็ก ๆ
> โดยพิสูจน์ผลในระดับ net P&L แบบ out-of-sample**

สังเกตว่านิยามนี้**ไม่บังคับ**ว่าต้องมี:

- cointegration
- copula
- OU
- PCA
- pair trading

เครื่องมือเหล่านี้เป็นเพียงชิ้นส่วน สิ่งที่ขาดไม่ได้คือสามอย่าง:
**การลด common risk**, **จำนวนเดิมพันที่มากพอ**, และ
**การพิสูจน์ที่ระดับ net OOS**

---

## 11.8 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. StatArb เป็นสถาปัตยกรรม ไม่ใช่โมเดล — แต่ละชั้นตอบคนละคำถาม
2. ในคริปโตต้องหัก common factor ก่อนเสมอ (PC1 อธิบาย 60–80% ของความแปรปรวน)
3. วาง copula ในสาย context/risk แล้วรวมแบบ overlay มักดีกว่าใช้เป็นตัวกรองแบบ AND

---

## แบบฝึกหัด

**11.1** ทำ PCA กับ return รายวันของเหรียญที่มีในรีโปนี้ PC1 อธิบาย
ความแปรปรวนกี่เปอร์เซ็นต์ แล้วดู loading — มันคือ "ตลาด" จริงไหม

**11.2** สร้าง baseline ตามสัปดาห์ที่ 1 ของหัวข้อ 11.6 ให้จบ
บันทึก Sharpe, turnover, hit rate ไว้เป็นเลขอ้างอิงสำหรับบทที่ 12

**11.3** เทียบสัญญาณเดียวกันที่คำนวณจาก raw return กับจาก residual
จำนวนสัญญาณต่างกันแค่ไหน และสัญญาณที่หายไปตอนใช้ residual คือคู่แบบไหน

**11.4** เขียนคำตอบของสามคำถามในหัวข้อ 11.5 สำหรับ copula ในระบบของคุณ
เป็นข้อความ ถ้าเขียนข้อ 3 ไม่ได้ นั่นคือสัญญาณที่ต้องแก้ก่อนเขียนโค้ดต่อ
