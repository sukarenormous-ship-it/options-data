# บทที่ 13 — หลุมพรางและกฎตัดสินโมเดล

> **บทนี้ตอบ:** เมื่อไรควรเก็บ copula ไว้ เมื่อไรควรทิ้งไปเลย

---

## 13.1 จุดอ่อนแปดข้อของ copula ที่ต้องจำ

**1. สถานะผิดปกติไม่ได้แปลว่าจะกลับ**
```
Rare ≠ Predictable
```
บทที่ 9 ทั้งบทว่าด้วยเรื่องนี้ และมันคือจุดอ่อนที่ทำให้คนเสียเงินมากที่สุด

**2. marginal ผิด → input ของ copula ผิด**
โดยเฉพาะการไม่กรอง vol clustering ซึ่งสร้าง tail dependence ปลอมได้ง่าย
(บทที่ 2)

**3. dependence เปลี่ยนตาม regime**
โครงสร้างที่ fit จากปีที่แล้วอาจใช้กับปีนี้ไม่ได้ และคุณจะรู้ตัวช้า
เพราะการประมาณค่าเป็นแบบเลื่อนหน้าต่าง (บทที่ 6)

**4. ทางเลือกเยอะเกินไป → overfit ง่ายมาก**
family × rotation × window × threshold × ความถี่ refit — พื้นที่ค้นหา
ใหญ่จนหาสิ่งที่ "ได้ผล" ในอดีตได้เสมอ (บทที่ 4, 12)

**5. หลายมิติซับซ้อนแบบระเบิด**
Vine ที่ d=8 มีโครงสร้างเป็นไปได้หลายร้อยล้านแบบ (ภาคผนวก D)

**6. turnover สูง → ต้นทุนกินหมด**
สัญญาณ copula เต้นเร็วกว่า z-score เพราะไวต่อสถานะร่วม
ซึ่งแปลว่าเข้าออกบ่อยกว่า

**7. tail dependence อาจเป็นข้อมูลความเสี่ยง ไม่ใช่ alpha**
รู้ว่าจะพังพร้อมกันมีค่ามาก แต่นั่นบอกให้ *ลดขนาด* ไม่ได้บอกให้ *เข้าเทรด*

**8. fit ดีขึ้นใน-sample ไม่ได้แปลว่า P&L ดีขึ้น OOS**
likelihood กับ P&L เป็นคนละฟังก์ชันเป้าหมาย และไม่มีเหตุผลทางทฤษฎีใด
ที่รับประกันว่าจะไปทางเดียวกัน

---

## 13.2 สี่อย่างที่ไม่ควรทำ

**1. เลือกคู่เพราะ correlation สูง แล้วเทรดเลย**
correlation สูงในคริปโตส่วนใหญ่คือ "ทั้งคู่ตาม BTC" ไม่ใช่ความสัมพันธ์
เฉพาะที่เทรดได้ (บทที่ 8, ภาคผนวก D)

**2. ADF ผ่านแล้วถือว่ามี edge**
p-value ไม่สร้างแรงดึงกลับในตลาด และ ADF บนข้อมูล 250 จุด
มี power ต่ำมากอยู่แล้ว ถ้าคุณทดสอบ 500 คู่ จะมีคู่ที่ "ผ่าน" หลายสิบคู่
โดยบังเอิญ

**3. copula บอกความน่าจะเป็นต่ำ แล้วคิดว่าต้องกลับ**
การกระโดดครั้งที่ 2 และ 3 ในบทที่ 9

**4. เพิ่มความซับซ้อนไปเรื่อย ๆ เพราะ backtest ดีขึ้น**
อันตรายที่สุด เพราะมันให้ผลตอบรับเชิงบวกทันทีทุกครั้ง —
ความซับซ้อนที่เพิ่มขึ้น *จะ* ทำให้ backtest ดีขึ้นเสมอ
นั่นคือนิยามของ overfitting ไม่ใช่หลักฐานว่ามันดีขึ้นจริง

## 13.3 กฎตัดสินโมเดล

```
┌──────────────────────────────────────────┐
│                                          │
│      Complexity must earn its keep       │
│                                          │
└──────────────────────────────────────────┘
```

สมมติสถานการณ์จริง:

```
โมเดลง่าย (OU):        Sharpe = 1.20
โมเดล + copula:        Sharpe = 1.25
```

ดูเผิน ๆ copula ชนะ แต่ให้ดูตารางเต็ม:

| มิติ | OU เดี่ยว | + Copula |
|---|---|---|
| Sharpe (OOS) | 1.20 | 1.25 |
| จำนวนพารามิเตอร์ | 3 | 10 |
| Turnover ต่อปี | 12× | 20× |
| ความไวต่อพารามิเตอร์ | ต่ำ | สูง |
| อธิบายให้คนอื่นเข้าใจ | ง่าย | ยาก |
| เวลาที่ใช้ debug ตอนพัง | ชั่วโมง | วัน |
| ความเสถียรข้าม regime | ดี | ยังไม่รู้ |

**ผมจะเลือกโมเดลง่าย** และเหตุผลไม่ใช่ความขี้เกียจ แต่เป็นเรื่องของ
การประมาณค่า:

ส่วนต่าง Sharpe 0.05 มี standard error เท่าไร?

สำหรับ Sharpe รายปี ค่าประมาณคร่าว ๆ คือ

```
SE(Sharpe รายปี)  ≈  1 / √(จำนวนปี)
```

ที่ข้อมูล 3 ปีจึงได้ SE ≈ **0.58** — **ส่วนต่าง 0.05 จมอยู่ใน
ความคลาดเคลื่อนอย่างสิ้นเชิง** ขณะที่ต้นทุนทั้งหมดในตารางเป็นของจริงและแน่นอน

(และสังเกตว่าสูตรนี้บอกอีกเรื่องที่เจ็บกว่า: ต่อให้ Sharpe จริงต่างกัน 0.3
คุณก็ต้องการข้อมูลราว 10 ปีจึงจะแยกมันออกจากศูนย์ได้อย่างมั่นใจ)

> คุณกำลังจ่ายความซับซ้อนที่แน่นอน เพื่อแลกกับกำไรที่วัดไม่ได้

**เมื่อไรที่ความซับซ้อนคุ้ม**

- ส่วนต่างใหญ่พอเมื่อเทียบกับ standard error ของมัน (ไม่ใช่แค่ "ดูมากกว่า")
- ส่วนต่างเสถียรในทุกช่วงเวลาย่อย ไม่ใช่มาจากช่วงเดียว
- **มีคำอธิบายว่าทำไมมันควรช่วย** ที่เขียนออกมาเป็นข้อความได้ก่อนเห็นผล
- มันช่วยในมิติที่คุณต้องการจริง (เช่น ลด MaxDD ไม่ใช่แค่เพิ่ม Sharpe)

## 13.4 หลักการที่สรุปทั้งเล่ม

> **อย่าตามหาโมเดลวิเศษตัวเดียว
> สร้างระบบโดยให้แต่ละโมเดลทำหน้าที่ของตัวเอง**

```
Factor          →   โครงสร้าง
OU / ง่าย ๆ      →   การกลับสู่ค่าเฉลี่ย / alpha
Copula          →   บริบทแบบมีเงื่อนไข / tail dependence
Portfolio       →   การทำให้เป็นกลาง / การกระจายความเสี่ยง
Execution       →   edge ที่เหลือจริง
```

และสุดท้าย **ให้ข้อมูล out-of-sample เป็นคนตัดสินว่าองค์ประกอบไหน
สมควรอยู่ต่อ**

Quant ที่ดีไม่ได้หาโมเดลที่ซับซ้อนที่สุด แต่หา
**โมเดลที่ง่ายที่สุดซึ่งจับกลไกเศรษฐศาสตร์ได้เพียงพอ**

## 13.5 รายการตรวจสอบก่อน deploy

```
โครงสร้างข้อมูล
  □ หัก common factor แล้ว
  □ marginal กรอง vol dynamics แล้ว
  □ ไม่มี look-ahead ใน rank / CDF / β / การเลือก family
  □ universe รวมสิ่งที่ delist ไปแล้ว

สัญญาณ
  □ forward return แยกตามถัง เป็น monotone
  □ ทดสอบ execution delay +1 บาร์ แล้ว edge ยังอยู่
  □ พิสูจน์ incremental value เหนือ baseline แล้ว (บทที่ 12)
  □ มีคำอธิบายเชิงกลไกว่าทำไมมันควรได้ผล

ความเสี่ยง
  □ คำนวณ effective breadth ที่ tail แล้ว
  □ มี stress scenario ที่ λ = 0.9 ทุกคู่
  □ รู้ว่าจะปิดระบบเมื่อไร (kill switch เชิงปริมาณ)

การดำเนินงาน
  □ ต้นทุนที่ใช้ในการทดสอบสมจริง (ทดสอบด้วยการเทรดจริงเล็ก ๆ ก่อน)
  □ มีเกณฑ์ล่วงหน้าว่าผลแบบไหนถือว่า "พัง" และต้องหยุด
  □ บันทึกจำนวนการทดลองทั้งหมดที่เคยทำกับข้อมูลชุดนี้
```

รายการสุดท้ายสำคัญกว่าที่คิด: **ถ้าคุณไม่ได้เขียนไว้ล่วงหน้าว่าผลแบบไหน
จะทำให้คุณหยุด คุณจะไม่มีวันหยุด** เพราะทุกช่วงขาดทุนจะดูเหมือน
"ช่วงที่ต้องอดทน" เสมอ

---

## 13.6 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. ความซับซ้อนต้องพิสูจน์ค่าตัวเอง และส่วนต่างต้องใหญ่กว่า standard error ของมัน
2. สี่สิ่งที่ไม่ควรทำ: เทรดตาม correlation, เชื่อ ADF, เชื่อว่าหายาก=จะกลับ,
   เพิ่มความซับซ้อนตาม backtest
3. อย่าหาโมเดลวิเศษ — ให้แต่ละโมเดลทำหน้าที่ของมัน แล้วให้ OOS ตัดสิน

---

## 13.7 ปิดท้าย

หนังสือเล่มนี้เริ่มจากคำถามว่า copula เอาไปทำอะไรได้ และเดินมาจบที่
ข้อสรุปที่อาจไม่ใช่สิ่งที่คาดไว้ตอนเริ่ม:

**เราไม่ได้ค้นพบว่า "ต้องใช้ copula"**

เราค้นพบสิ่งที่มีค่ากว่า — ว่าคำถาม "โมเดลไหนดีที่สุด" เป็นคำถามที่ผิด
ตั้งแต่แรก และสิ่งที่ควรสร้างคือระบบที่แต่ละชิ้นส่วนตอบคำถามของตัวเอง
ได้ชัดเจน โดยมีข้อมูล out-of-sample เป็นผู้ตัดสินสุดท้ายว่าชิ้นไหน
สมควรอยู่ต่อ

Copula เป็นชิ้นส่วนที่ดีชิ้นหนึ่งในระบบนั้น — ถ้าวางไว้ถูกที่

```
        Market Returns
              ↓
      Common Factor Model
              ↓
          Residuals
              ↓
   Simple Mean-Reversion / Ranking
              ↓
    Copula Conditional Context
              ↓
      Long-Short Portfolio
              ↓
    Factor / Tail Risk Control
              ↓
      Execution + Costs
              ↓
    ══ NET OOS P&L ══
```

และลูกศรสุดท้ายสำคัญที่สุดเสมอ

## แบบฝึกหัด

**13.1** ทำตารางเปรียบเทียบแบบหัวข้อ 13.3 สำหรับระบบของคุณเอง
พร้อมคำนวณ standard error ของส่วนต่าง Sharpe
(ใช้ `SE ≈ 1/√(จำนวนปี)` แล้วตรวจด้วย bootstrap อีกครั้ง —
ค่าจาก bootstrap มักกว้างกว่าสูตร เพราะผลตอบแทนจริงไม่ได้เป็น iid normal)

**13.2** เขียนเกณฑ์ kill switch ของระบบคุณเป็นตัวเลขที่ชัดเจน
ล่วงหน้า ก่อนเริ่มเทรดจริง

**13.3** กลับไปอ่านคำตอบที่คุณเขียนไว้ในแบบฝึกหัด 2.4 ตอนนี้คุณ
ตอบเหมือนเดิมไหม

**13.4** เขียนสรุปหนึ่งหน้าว่า copula อยู่ตรงไหนในระบบของคุณ
ตอบคำถามอะไร และคุณจะรู้ได้อย่างไรว่ามันควรถูกเอาออก
ถ้าเขียนไม่ได้ ให้กลับไปบทที่ 11 หัวข้อ 11.2
