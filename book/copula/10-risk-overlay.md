# บทที่ 10 — Copula ในบทบาท risk overlay

> **บทนี้ตอบ:** 20 คู่ที่ถืออยู่ จริง ๆ แล้วเป็นกี่เดิมพัน
> และทำไมบทบาทนี้อาจเป็นการใช้ copula ที่คุ้มค่าที่สุด

---

## 10.1 ทำไมบทนี้อาจสำคัญกว่าบทที่ 7

บทที่ 7 ใช้ copula ทำนาย ซึ่งเป็นงานที่มันไม่ได้ถูกออกแบบมาให้ทำ (บทที่ 8)

บทนี้ใช้ copula **อธิบายโครงสร้างการพึ่งพา** ซึ่งเป็นงานที่มันถูกสร้างมา
เพื่อสิ่งนี้โดยตรง

```
ใช้เป็น alpha:  ต้องเดิมพันว่า "หายาก ⟹ จะกลับมา"     ← สมมติฐานที่พิสูจน์ยาก
ใช้เป็น risk:   แค่ต้องการรู้ว่า "อะไรพังพร้อมกันได้"   ← สิ่งที่ copula ตอบได้ตรง ๆ
```

**เมื่อใช้เป็น risk overlay คุณได้ประโยชน์จาก copula โดยไม่ต้องพึ่ง
สมมติฐานที่เปราะที่สุด** นั่นคือเหตุผลที่ผมคิดว่านี่คือ use case
ที่แข็งแรงที่สุด

---

## 10.2 ปัญหา: nominal breadth ≠ effective breadth

Fundamental Law of Active Management:

```
IR ≈ IC · √breadth
```

พูดว่า: ผลตอบแทนต่อความเสี่ยงขึ้นกับคุณภาพของสัญญาณ (IC)
คูณด้วยรากที่สองของ**จำนวนเดิมพันอิสระ**

คำสำคัญคือ **อิสระ**

สมมติคุณถือ 20 คู่ long-short ในคริปโต ถ้าทุกคู่เป็น
"long altcoin / short BTC" ในรูปแบบต่าง ๆ คุณไม่ได้มี 20 เดิมพัน
คุณมี **1 เดิมพัน คูณ 20**

สูตรประมาณ effective breadth เมื่อ pairwise correlation เฉลี่ยเท่ากับ ρ̄:

```
N_eff = N / ( 1 + (N−1)·ρ̄ )
```

ลองใส่ตัวเลข N = 20:

| ρ̄ | N_eff | IR เทียบกับกรณีอิสระ |
|---|---|---|
| 0.00 | 20.0 | 100% |
| 0.05 | 10.3 | 72% |
| 0.15 | **5.2** | **51%** |
| 0.30 | 3.0 | 39% |
| 0.70 | **1.4** | **27%** |

**สองแถวที่ทำให้เจ็บ:** ρ̄ = 0.15 ซึ่งดู "กระจายดี" ให้เดิมพันจริงแค่ 5 ครั้ง
และถ้า ρ̄ พุ่งเป็น 0.70 ในวันที่แย่ที่สุด คุณเหลือ **1.4 เดิมพัน** —
คือแทบเป็นสถานะเดียว ในวันที่คุณต้องการการกระจายความเสี่ยงมากที่สุด

**Copula คือเครื่องมือที่วัดแถวสุดท้ายนั้นได้ ส่วน correlation matrix
วัดได้แค่แถวกลาง ๆ**

## 10.3 มาตรวัดสี่ตัวที่ควรติดตามทุกวัน

### 1. Tail dependence matrix

แทนที่จะดู correlation matrix ให้ดู `λ_L` ของทุกคู่ในพอร์ต

```
         P&L₁   P&L₂   P&L₃   ...
P&L₁      —    0.42   0.08
P&L₂     0.42    —     0.51
P&L₃     0.08   0.51    —
```

ค่าสูงหมายถึง "สองสถานะนี้มีแนวโน้มขาดทุนหนักพร้อมกัน"
คู่ที่ `λ_L` สูงคือคู่ที่ไม่ได้กระจายความเสี่ยงให้กันเลยในเวลาที่สำคัญ

### 2. Joint exceedance probability

```
P( ทุกสถานะใน S ขาดทุนเกิน percentile ที่ 5 พร้อมกัน )
```

เทียบสามค่าเสมอ:

```
ภายใต้ความเป็นอิสระ:  0.05^k               ← เล็กมาก
ภายใต้ Gaussian:      คำนวณจาก Φ_Σ         ← ใหญ่ขึ้น
ภายใต้ t / Clayton:   คำนวณจาก copula      ← ใหญ่กว่ามาก
```

**อัตราส่วนระหว่างค่าที่สามกับค่าแรก คือตัวเลขที่บอกว่าคุณกำลัง
ประเมินความเสี่ยงต่ำไปกี่เท่า** ถ้าใช้สมมติฐานที่ง่ายเกินไป

ตัวเลขนี้อาจอยู่ระดับ 10× ถึง 100× ได้ง่าย ๆ ในพอร์ตคริปโต

### 3. Conditional drawdown

```
E[ ขาดทุนรวมของพอร์ต | สถานะที่ใหญ่ที่สุดขาดทุนเกิน percentile 1 ]
```

ตอบคำถามที่ตรงกับความกังวลจริง: **"วันที่ตัวใหญ่สุดพัง พอร์ตทั้งหมดพังแค่ไหน"**
คำนวณจาก copula ที่ fit ไว้ ผ่านการสุ่มแบบมีเงื่อนไข

### 4. Effective breadth ที่ tail

คำนวณ `N_eff` สองครั้ง: ครั้งหนึ่งจาก correlation ปกติ อีกครั้งจาก
tail dependence

```
N_eff (ปกติ)  = 5.2
N_eff (tail)  = 1.4    ← ตัวเลขที่ควรใช้ตั้ง risk limit
```

**ตั้ง limit จากตัวเลขที่สอง** ไม่ใช่ตัวแรก

## 10.4 เอาไปใช้ปรับ position sizing อย่างไร

**การใช้แบบที่ 1 — ปรับขนาดตาม tail crowding**

```
w_i ← w_i · f( λ̄_i )       โดย λ̄_i = ค่าเฉลี่ย tail dependence ของสถานะ i
                            กับสถานะอื่นทั้งหมดในพอร์ต
```

สถานะที่ "ซ้ำกับคนอื่น" ตอน tail ได้ขนาดเล็กลง แม้สัญญาณ alpha จะแรงเท่ากัน

**การใช้แบบที่ 2 — เพดานรวมตาม cluster**

จัดกลุ่มสถานะด้วย tail dependence (ไม่ใช่ correlation) แล้วตั้งเพดาน
ความเสี่ยงต่อกลุ่ม

```
กลุ่ม A: long altcoin beta         →  เพดาน 30% ของ risk budget
กลุ่ม B: term structure ของ IV     →  เพดาน 30%
กลุ่ม C: cross-exchange basis      →  เพดาน 40%
```

การจัดกลุ่มด้วย tail dependence มักให้ผลต่างจากการจัดด้วย correlation
อย่างมีนัยสำคัญ — และต่างในทิศที่สำคัญ (มันรวมสิ่งที่พังพร้อมกันเข้าด้วยกัน)

**การใช้แบบที่ 3 — ตัวคูณความเสี่ยงตาม regime**

เมื่อ `λ` ที่ประมาณได้ทั้งพอร์ตพุ่งขึ้น (เข้าสู่ regime ที่ทุกอย่างเกี่ยวกันหมด)
ลด gross exposure ลงทั้งกระดาน

นี่เป็นกฎที่เรียบง่ายและมักให้ผลดีกว่าการพยายามทำนายอะไรทั้งสิ้น
เพราะมันตอบสนองต่อสิ่งที่**สังเกตได้แล้ว** ไม่ใช่สิ่งที่ต้องทำนาย

---

## 10.5 ตัวอย่างที่ทำให้เห็นภาพ

พอร์ตสมมติในคริปโต:

```
สถานะ 1:  long ETH   / short BTC
สถานะ 2:  long SOL   / short BTC
สถานะ 3:  long AVAX  / short BTC
สถานะ 4:  long ETH   / short SOL
สถานะ 5:  long perp  / short spot (basis)
```

**มองด้วยตาเปล่า:** 5 สถานะ ดูกระจาย มีทั้ง relative value และ basis

**มองด้วย correlation ของ P&L:** สถานะ 1–3 มี correlation ราว 0.6 ต่อกัน
เพราะทั้งหมดคือ "long altcoin beta" สถานะ 4 เป็นกลางกว่า สถานะ 5 ดูเป็นอิสระ

**มองด้วย tail dependence:** สถานะ 1–3 มี `λ_L` ราว 0.7
และ — นี่คือส่วนที่คนพลาด — **สถานะ 5 ก็มี `λ_L` สูงกับกลุ่มนั้นด้วย**
เพราะในวัน liquidation cascade basis จะขยายพร้อมกับที่ altcoin ร่วง
ทั้งที่ในวันปกติมันไม่เกี่ยวกันเลย

**ข้อสรุป:** พอร์ตนี้มี effective breadth ที่ tail ประมาณ 1.5–2
ไม่ใช่ 5 และนี่คือข้อมูลที่ correlation matrix ไม่บอกคุณ

---

## 10.6 ข้อควรระวัง

**1. tail dependence ประมาณยากมาก**
ย้ำจากบทที่ 5: `λ` ถูกประมาณจากข้อมูลไม่กี่จุดเสมอ ให้ใช้มันเป็น
**การจัดอันดับ** (คู่ไหนเสี่ยงกว่าคู่ไหน) มากกว่าเป็นตัวเลขที่แม่นยำ

**2. P&L ของกลยุทธ์ไม่ใช่ return ของสินทรัพย์**
ต้องคำนวณ dependence บน P&L ของสถานะจริง ไม่ใช่ของสินทรัพย์อ้างอิง
เพราะ hedge ratio, การเข้าออก และ stop เปลี่ยนโครงสร้างไปหมด

**3. อดีตไม่ครอบคลุมทุกวิกฤต**
ถ้าข้อมูลของคุณไม่มีเหตุการณ์แบบ COVID crash, LUNA, FTX
`λ` ที่ประมาณได้จะต่ำเกินจริง ควรทำ **stress scenario ด้วยมือ** เพิ่ม:
"ถ้า λ ของทุกคู่เป็น 0.9 พอร์ตนี้เสียเท่าไร"

**4. อย่าให้ risk overlay กลายเป็น alpha model**
บทบาทของมันคือลดขนาดเมื่อเสี่ยง ไม่ใช่ทำนายว่าเมื่อไรจะเสี่ยง
ถ้าเริ่มพยายามทำนาย คุณกลับไปอยู่ในกับดักของบทที่ 8 แล้ว

---

## 10.7 สิ่งที่ควรจำจากบทนี้

**สามบรรทัดสรุป**

1. `N_eff = N/(1+(N−1)ρ̄)` — 20 สถานะที่ ρ̄=0.15 คือ 5 เดิมพัน
   และที่ ρ̄=0.7 คือ 1.4 เดิมพัน
2. ตั้ง risk limit จาก effective breadth **ที่ tail** ไม่ใช่ที่ค่าเฉลี่ย
3. บทบาท risk overlay ใช้สิ่งที่ copula ทำได้ดีจริง โดยไม่ต้องพึ่ง
   สมมติฐานเรื่อง reversion เลย — จึงเป็น use case ที่แข็งแรงที่สุด

## แบบฝึกหัด

**10.1** คำนวณ `N_eff` ของพอร์ตปัจจุบันของคุณสองแบบ: จาก correlation ปกติ
และจาก correlation ที่คำนวณเฉพาะวันที่ตลาดลง 10% แย่ที่สุด
ตัวเลขต่างกันเท่าไร

**10.2** fit Student-t copula กับ P&L รายวันของสถานะทั้งหมด แล้วคำนวณ
`P(ทุกสถานะขาดทุนเกิน percentile 5 พร้อมกัน)` เทียบกับค่าภายใต้
ความเป็นอิสระ อัตราส่วนเป็นเท่าไร

**10.3** จัดกลุ่มสถานะสองครั้ง — ด้วย correlation และด้วย tail dependence
กลุ่มที่ได้ต่างกันไหม ต่างตรงไหน

**10.4** ทำ stress test: บังคับให้ทุกคู่มี λ = 0.9 แล้วจำลองผลตอบแทน
พอร์ต 10,000 เส้นทาง ค่า 1% ที่แย่ที่สุดคือเท่าไร เทียบกับ VaR ปกติของคุณ
