## งาน B — บท "การรวมสัญญาณโดยไม่ overfit"

**ไฟล์:** `statarb-signal-blending.html` · ต่อจาก `statarb-copula-practice.html`

### คำถามที่บทต้องตอบ
ตอนนี้ผู้อ่านมี z-score + Mispricing Index + regime filter + cost filter — **รวมยังไงโดยไม่ทำลาย edge ของตัวเอง**

### โครง
1. ทำไมการเพิ่มตัวกรองถึง *ดูดีขึ้นเสมอ* ใน in-sample
2. สามวิธีรวม: **voting** (นับเสียง) · **weighting** (ถ่วงน้ำหนัก) · **gating** (ตัวหนึ่งเปิดประตูให้อีกตัว) — พร้อมข้อดี/ข้อเสียและจำนวนพารามิเตอร์ที่แต่ละแบบกิน
3. **งบ degrees of freedom** — กฎนิ้วโป้งว่าข้อมูล n ตัวอย่างรองรับพารามิเตอร์ได้กี่ตัว
4. **meta-labelling** (López de Prado) — แยก "จะเข้าไหม" ออกจาก "จะเข้าเท่าไร" ซึ่งเป็นวิธีรวมที่กิน DoF น้อยที่สุด (คลังมีแค่ 3 ครั้ง · triple-barrier = 0)
5. วิธีวัดว่าตัวกรองที่เพิ่มให้มูลค่าจริง

### ตัวเลขที่คำนวณได้จริง ⭐
ใช้เครื่องจักรเดียวกับ Part 8 ที่วัด "ค่าปรับจากการค้นหา" ได้ 4.77 จุด
- สร้างตัวกรอง 4 ตัวบน BTC/ETH (z · MI · regime · cost) แล้วลอง **ทุกวิธีรวมที่เป็นไปได้**
- วัดว่าวิธีที่ดีที่สุด "ดีขึ้น" เท่าไรจากตัวเดียว
- แล้วรันการค้นหาชุดเดียวกันบน **ข้อมูลที่ไม่มีโครงสร้าง** → ได้ตัวเลขว่าการรวมสัญญาณล้วน ๆ เสกผลงานปลอมได้กี่จุด
- นี่จะเป็นตัวเลขที่ตอบคำถามทั้งบทในบรรทัดเดียว

### เกณฑ์เสร็จ
อ่านจบแล้วตอบได้ว่า "ตัวกรองที่ฉันเพิ่งเพิ่ม คุ้มกับ DoF ที่มันกินไหม" และมีวิธีวัดที่ทำเองได้

### สถานะละเอียด (อัปเดตหลังลงมือทำจริง)

## งาน C — บท "live กับ backtest ไม่ตรงกัน"

**ไฟล์:** `statarb-live-vs-backtest.html`

### คำถามที่บทต้องตอบ
**จะรู้ได้ยังไงว่าระบบที่รันอยู่กำลังพัง** ก่อนที่จะเสียเงินไปมาก

### โครง
1. สามชั้นที่ทำให้ live ต่างจาก backtest: **ราคาที่ได้จริง** · **สิ่งที่วัด** · **สิ่งที่เกิดขึ้นแต่ backtest ไม่รู้**
2. เคสจริงจากคลัง — บอทวัด drawdown จากยอด USDT อย่างเดียว ทำให้ backtest กับ live วัดคนละอย่าง (มีอยู่แล้วในรายงานรีวิว grid ยกมาใช้)
3. **การกระทบยอดทีละ fill** — เทียบราคาที่ backtest คิดกับที่ได้จริงทุกไม้ ไม่ใช่ดูแค่ผลรวม
4. **งบ tracking error** — ตั้งเพดานไว้ก่อนว่าต่างได้เท่าไร แล้วหยุดเมื่อเกิน
5. **shadow trading** — รันคู่ขนานโดยไม่ลงเงิน ใช้เมื่อไรถึงคุ้ม
6. เช็กลิสต์รายวัน / รายสัปดาห์

### ตัวเลขที่คำนวณได้จริง ⭐
- backtest ที่สมมติ fill ที่ราคากลาง เทียบกับที่จ่ายราคาเสนอขายจริงจากกระดานในคลัง → **ช่องว่างเป็นจุดเปอร์เซ็นต์ต่อรอบ แยกตามอายุสัญญา** (ต่อยอดจากตัวเลข 22.5% / 2.3% ใน Part 5)
- จากไฟล์ล่าสุด: **46% ของสัญญาทั้งกระดานไม่มีปริมาณซื้อขายเลยใน 24 ชม.** → backtest ที่สมมติว่าเทรดได้ทุกตัวกำลังโกหก
- **10% ไม่มีราคาเสนอซื้อ** และ **13 สัญญามี mark price อยู่นอกช่วง bid-ask** → ราคาที่ backtest ใช้อาจไม่มีอยู่จริง

### เกณฑ์เสร็จ
มีเช็กลิสต์ที่เอาไปใช้ได้ทันที และมีตัวเลขว่าช่องว่าง live/backtest ของตลาดนี้ใหญ่แค่ไหน

## งาน D — บท "edge เสื่อม — แยกจาก drawdown ปกติยังไง"

**ไฟล์:** `statarb-alpha-decay.html`

### คำถามที่บทต้องตอบ
ขาดทุนติดกันสองเดือน — **edge หายไปแล้ว หรือแค่ช่วงแย่ตามปกติ**

### โครง
1. ทำไมคำถามนี้ถึงตอบยากกว่าที่คิด (ต่อจากคณิตศาสตร์ของ Part 1 โดยตรง)
2. **คำตอบที่ซื่อสัตย์: ส่วนใหญ่คุณแยกไม่ออก** และนี่คือจำนวนไม้ที่ต้องใช้ถึงจะแยกได้
3. สาเหตุที่ edge เสื่อมจริง ๆ — คนแห่ทำตาม (crowding) · โครงสร้างตลาดเปลี่ยน · ต้นทุนเพิ่ม · ระบอบตลาดเปลี่ยน
4. สัญญาณเตือนที่มาก่อนตัวเลขผลตอบแทน: turnover เปลี่ยน · เวลาถือไม้เปลี่ยน · สเปรดที่เข้าได้แคบลง
5. **จะทำอะไรระหว่างที่ยังไม่รู้** — ลดขนาดตามสัดส่วนความไม่แน่ใจ ไม่ใช่ปิดหรือเดินหน้าเต็มที่

### ตัวเลขที่คำนวณได้จริง ⭐
ใช้เครื่องจักรเดียวกับ `nq-tool-samplesize`
- ถ้า edge เดิม 55% เสื่อมเหลือ 50% ต้องใช้กี่ไม้ถึงจะ *ตรวจจับได้* ด้วยความมั่นใจ 90%
- ทำตารางว่า edge ขนาดต่าง ๆ ใช้เวลาตรวจจับต่างกันแค่ไหน
- ผลที่คาดว่าจะได้และเป็นประเด็นของบท: **เวลาที่ใช้ตรวจจับการเสื่อม ยาวกว่าเวลาที่คนส่วนใหญ่ทนได้**

### เกณฑ์เสร็จ
ผู้อ่านมีกฎที่ตั้งไว้ล่วงหน้าได้ว่าจะลดขนาดเมื่อไรและเท่าไร แทนการตัดสินใจตอนกำลังเจ็บ

### คำถามที่บทต้องตอบ
backtest ของคุณตั้งอยู่บนข้อมูล — **ข้อมูลนั้นมีปัญหาอะไรบ้างที่คุณมองไม่เห็น**

### โครง
1. หกโรคของข้อมูล: **ผู้รอดชีวิต · ข้อมูลที่ถูกแก้ย้อนหลัง · มองอนาคต · quote ที่ไม่มีจริง · สภาพคล่องปลอม · เหตุการณ์บริษัท**
2. ฝั่งคริปโตโดยเฉพาะ: เหรียญที่ถูก delist · wick ที่เกิดจาก liquidation cascade · ประวัติ funding ที่ถูกแก้ · ราคาต่างกันข้ามตลาด
3. **ขาช็อตยืมของได้จริงไหม** (คลังมีแค่ 3 ครั้ง) — backtest ที่ช็อตอะไรก็ได้ตลอดเวลาไม่มีอยู่จริง
4. วิธีตรวจข้อมูลของตัวเองก่อนใช้ — สคริปต์ตรวจสุขภาพข้อมูล

### ตัวเลขที่คำนวณได้จริง ⭐ (ตรวจคลังของเราเองแล้ว)
- **44%** ของสัญญาที่มีอยู่วันแรก รอดถึงวันสุดท้าย (ใช้ใน Part 1 แล้ว ขยายความที่นี่)
- **46%** ของสัญญาไม่มีปริมาณซื้อขายเลยใน 24 ชม.
- **10%** ไม่มีราคาเสนอซื้อ · **13 สัญญา** mark price อยู่นอกช่วง bid-ask
- **0 ช่วงที่ข้อมูลขาดหาย** และ deribit/okx ครบ 57 วันตรงกันทั้งคู่ — ข่าวดีที่ต้องรายงานด้วย
